The platform does the cross-checking a checker does by hand: is this tag drawn on its home sheet, does the JB on the schematic match the JB on the cable block diagram, does the termination drawing send this device to the PLC slot the schematic shows. It reads every sheet, turns what it reads into facts with a location, joins the facts into one model of the system, and runs rules over that model. Every finding names the sheet and grid cell so a person can find it, judge it, and fix the drawing.

01What it is for

A controls package describes one system three ways. The PLC schematics show each I/O module and, row by row, the field device on each channel, its wire numbers and the junction box (JB) it goes through. The cable block diagrams (CBDs) show the cables: which device is in which enclosure and which cable runs from each JB to the PLC panel. The termination drawings show each JB's terminal strip: which wire lands on which terminal, which device it serves, and which panel slot it goes to.

The three descriptions are drawn by hand and drift apart. A device gets copied to a new sheet and keeps its old tag. A JB is renamed on one drawing but not another. A cable number is left as CXXXXX. The platform finds those disagreements.

Ground rules

Read-only. It never changes a drawing. PDFs are opened read-only and never saved; every run records each input file's SHA-256 fingerprint.

Code decides. Every check is a rule written as code with tests, so the same drawings always give the same findings. No AI is used anywhere in the current build.

Every finding quotes its evidence: drawing, sheet, grid cell and the text exactly as drawn.

A person decides. The checker confirms, rejects or defers each finding in an Excel register, and those decisions carry forward to later runs.

02The pipeline

One command runs seven stages in order. Each stage only adds to what the previous one produced, and each records what it did (or why it could not) in the run's stage table, so a report always says plainly what was and was not checked.

StageCodeWhat it produces
1 Ingestingest/discovery.pyThe list of input files, each with its document type (from its folder), size and SHA-256. Problems (unknown folder, unreadable file, duplicate copy) become issues, not findings.
2 Readpdf/, parsers/Per sheet: title block, grid frame, and claims: small facts with their exact position.
3 Linklinker/, graph/One engineering model: a node per device, wire, JB, panel, module, channel and terminal, with typed edges between them.
4 Tracetraces/A signal trace per PLC channel, from the field device to the channel, plus orphan traces and coverage figures.
5 Rulesrules/Findings, plus an audit of every rule: ran, skipped (and why) or failed.
6 Reviewreview/Only with [review] enabled = true (off by default): the checker's decision put on every finding; what is new; what is no longer raised.
7 Outputsreport/The register, the readable report and two JSON files.

03Inputs

A package is one folder with up to four subfolders. The folder name decides the document type; matching ignores case and accepts aliases set in config/project.toml.

FolderTypeAccepted filesRead as
PLC/PLCPDFSchematic sheets: rack layout, one I/O module per slot sheet
CableBlocks/ · CBD/CBDPDFCable block diagrams: enclosures, devices, cables
Terminations/ · Terms/TERMPDFJB terminal strips and PLC slot terminal strips
EquipmentList/ · EEL/EQUIPxlsx, xls, csv, PDFListed only (its reader is parked with M8)

All four types are reviewed by default. Any type can be left out of a run with --exclude, for example termination drawings that are not up to the new standard. A left-out type is still found, fingerprinted and listed, but nothing is checked against it, no other check uses it, and the rules that need it are skipped with that reason. A missing folder for a left-out type is not a warning.

  1. Validate the root. The folder must exist; a missing type folder is a warning, because a partial package is still worth checking.
  2. Map folders to types; files outside the four folders, other file types and Office lock files (~$…) are listed and ignored.
  3. Fingerprint every file (SHA-256). Two identical files are a DUPLICATE_FILE issue and the copy is skipped.
  4. Open each PDF read-only. An encrypted or corrupt file is an UNREADABLE_FILE issue; the run carries on.
  5. One page, one sheet. Each page becomes a Drawing with its drawing number, sheet and revision from the title block.

04Reading a sheet

Where the text is

The client's PDFs have no text layer. AutoCAD plots its SHX fonts as line geometry, so ordinary PDF text extraction finds nothing. But AutoCAD also embeds every piece of text as an invisible annotation titled AutoCAD SHX Text, holding the text and its box. The reader takes the words from those annotations, which gives exact text and position with no OCR. A page with no text and an image is classed as a scan and flagged NEEDS_OCR (OCR is parked).

Plotting matters

The SHX notes are only there if AutoCAD's PDFSHX setting is 1 when the sheet is plotted. A sheet plotted with it at 0 is all line work: it has nothing to read, so no title block, grid or tags. The platform reports such a sheet as NO_SHX_TEXT ("drawn but its text cannot be read … re-plot it with PDFSHX set to 1", naming the AutoCAD version that plotted it), prints a warning at the end of the run, and checks nothing on it. A few TrueType words (a logo, a stamp) do not count as readable: a drawn sheet with no SHX notes and no title block is reported too. To check a PDF yourself, open its Comments list: it should show many entries titled AutoCAD SHX Text.

Title block

The title block in the bottom-right corner is read by its labels: the value nearest each label (Drawing N°, Sheet N°, Rev N°, the status such as PRELIMINARY, the title lines). The descriptor line (SCHEMATIC DIAGRAM, CABLING BLOCK DIAGRAM, TERMINATION DIAGRAM) is checked against the folder (DRW-004). Legend, symbol and index sheets are recognised by their descriptor and left out of the checks, because their example tags are not real content.

Grid frame

Every finding gives a grid cell. The reader finds the border labels: row letters down the left edge (A to Z, skipping I and O) and column numbers across the top (0 to 9). Any point on the sheet maps to the cell whose row and column centres are nearest.

A sheet whose title block cannot be read is identified from its file name instead, when it follows <drawing>-<sheet>.pdf (401002-490.pdf is drawing 401002, sheet 490). A sheet with no readable text still counts as in the package: references to it are not reported as missing sheets, and its unread title block is not reported again as incomplete.

Sheets that are identical copies of one already read (same drawing number, sheet and content hash, as in a merged schematic set) are skipped with a DUPLICATE_SHEET issue so nothing is counted twice. Copies with the same number but different content are both kept and reported (DRW-007).

The package follows a location-coded naming convention, and the identifier grammar (common/identifiers.py) is what lets the platform tell a device tag from a wire number from a JB, and know where each should be drawn.

Renamed designations

When a designation is renamed during a project, drawings that still use the old name are wrong, but the platform cannot know a rename happened unless it is told. Renames are listed in config/project.toml:

[project.superseded]
"LTL-AUT1" = "LTL-PLC"   # AUT renamed to PLC (confirmed by checker 2026-10-21)
"MCC-AUT1" = "MCC-PLC"   # example: add a line per old name, once the rename is confirmed

For every entry, two things happen on the next run:

  • Each use of the old name is reported by DRW-006, with the replacement as the recommendation ("Replace with =K07.11+LTL-PLC"), at its sheet and grid cell.
  • The old name is linked to the new one, so traces, JB terminals and PLC slots still join up: a stale name does not also break every check that follows it. The original spelling is kept as evidence.

Separately, any word in [placeholders] tokens (it includes AUT1 on this project) is reported wherever it appears, by PLACEHOLDER-005. That catches an old name before anyone has confirmed what replaces it. A legend that lists an old name the package uses nowhere else is reported by PATH-004. Add a rename only once the checker has confirmed it: until then those two rules keep the old name visible.

06Claims: the evidence layer

The readers never decide whether a drawing is right. They write down what they see as claims: one fact, from one place, on one sheet, read by one reader. Claims are never edited after they are made. Everything downstream (the model, the traces, the findings) is built from claims and points back to them, which is how every finding can quote its evidence.

07The three readers

Each document type has its own parser. Every parser first runs the shared occurrence reader (every identifier, placeholder and word on the sheet, with its cell), then the first template reader that recognises the sheet's layout. A sheet no template recognises still keeps its identifiers, and the report says so (NO_TEMPLATE).

PLC schematics

Rack layout sheet: slot numbers across the top, the module in each slot, and the schematic sheet each slot is drawn on. Slot sheets: one I/O module per sheet. The header gives the part number (1734-IB8S), the rack and slot, and the POINTS line (LTL.S13.DI.00..07). Below it, one row per channel.

Every schematic sheet's LEGEND box is read too: the JBs and locations the sheet routes through, each with its full designation. PATH-004 compares it with the JBs actually used in the sheet's channel rows.

Cable block diagrams

CBDs are read from their drawn lines, not only their text, using the client's CAD line weights.

Termination drawings

Two layouts are recognised. JB termination diagrams show each JB's terminal strip; PLC slot termination diagrams show each module's terminals and where each group goes out.

08Linking: one model of the system

The linker turns thousands of claims into one engineering model. Every distinct thing (by type and canonical key) becomes one node, however many sheets mention it. Every relationship becomes a typed edge that keeps the IDs of the claims behind it. A node seen by two or more drawing types is corroborated; one seen by one type is single source; one implied by another (a JB implied by a terminal key, a panel by a rack) is derived. The model is loaded into a networkx graph for path searches.

Two details matter. A superseded name such as LTL-AUT1 is linked to its replacement LTL-PLC, so traces are not broken by a stale name, while the original spelling is kept and DRW-006 still reports it. Slot termination sheets name a module only by slot (S12); the linker resolves it to the rack's module when only one rack has that slot.

09Signal traces

A signal trace follows one PLC signal through the system. One is built per PLC channel, walking backward from the channel through the model. Each step is a hop with a value and a status.

Hop statuses

found the drawings show it.

inferred device taken from the same-description channel on the same module.

missing the supplied drawings should show it and do not: a gap.

not sourced only a document type that is left out or not supplied could show it. Never a gap.

Trace statuses

Complete: every hop found.

Partial: reaches a channel, some hop missing or not sourced.

Orphan: a device on a CBD that no channel reaches.

Spare / Internal: a spare channel; a channel with no field device or JB (supply monitoring).

Conflicted (flag): two drawings disagree on a hop.

Special cases the builder handles: a device cabled straight to the panel on the CBD has no JB, and that is correct (direct to panel); every device in a row is reached, not only the first (a relay and its contact share a row); a device tag on a CBD under a wrong name is never taken as proof of a cable.

Coverage

Coverage summarises the traces per area, panel, PLC slot and JB / location. A field trace counts as traced when it is complete, or complete except hops that are only not sourced, and no two drawings disagree on it. On the sample package (terminations left out): 118 of 159 field traces are traced (74%); 7 have a gap, 23 are orphans and 11 are conflicted. Spare and internal channels are left out of the count.

10The rule engine

Each check is a rule: a small class with an ID (TAG-003), a title, a category, a default severity, a description, and a list of what it requires. The engine runs every registered rule against a read-only view of the run.

Rules see only checked sheets. Legend and symbol sheets, and every sheet of a left-out document type, are filtered out of the view before any rule runs. Rules iterate in sorted order and build messages from templates, so the same input always gives identical findings.

The 49 built rules fall into nine categories (the full list is in section 17):

12Review and carry-forward (optional)

Off by default. The register is normally printed and marked up by hand, so it carries no decision columns, and the review stage, the decision database, waivers and the No Longer Raised tab are all skipped. Set enabled = true under [review] in config/project.toml to switch everything in this section on. The code is unchanged either way.

With review on, the checker records decisions in QA_Register.xlsx, in the four yellow columns: Decision, Checker comment, Reviewed by, Date. Everything else in the register is rewritten every run.

DecisionMeaningOn later runs
OPENNot reviewed (default)Shown normally
CONFIRMEDA real problemStays on the register until the drawing is fixed
FALSE_POSITIVENot a problemGreyed out and struck through, with the comment, until the evidence changes
FIXEDFixed in the drawingsGreyed; once no longer raised, it drops off
WAIVEDA known exception, acceptedGreyed
DEFERREDDecide laterShown, marked grey

Edge cases handled

  • Register open in Excel. The run cannot overwrite a locked file, so it writes QA_Register-<run id>.xlsx and warns. The next run reads both (the most recently saved wins) and moves the copy to register_history/.
  • No Longer Raised. Findings the previous run raised but this run does not are listed once. Any with a decision other than FIXED stay listed until the checker marks them FIXED there, so a fix is confirmed rather than assumed.
  • Waivers. config/waivers.toml holds known, accepted exceptions: an ID, a rule pattern, a subject pattern (*, ?), a reason, an approver and an optional expiry. Matching findings show as WAIVED with "Waiver W-001: …". The checker's own decision wins. Expired waivers are listed but not applied, and a waiver that matches nothing is named in the run notes. Removing a waiver reopens its findings.
  • Changing which inputs are reviewed between runs into the same folder makes findings from the dropped type appear as no longer raised. Keep one --exclude setting per output folder.

Configuration

config/project.toml

In three parts: 1. Project (what belongs to one job), 2. Client drafting standard (the same for every package from the client), 3. Run preferences.

[project] everything specific to one project: code and name (labels only), known areas (LTL, RCL, SPL, SH, ES, EER1; areas the drawings write as a +AREA-… designation are learned each run), description_prefix, ffi_drawings (TN → 401103, TV/TH → EXTERNAL), superseded (LTL-AUT1 → LTL-PLC), rack_panels.

[ingest] folder aliases, types left out by default.

[identifiers] tag pattern parts, panel types, panel-device prefixes (K, Q).

[placeholders] tokens and phrases; [spelling] known real words.

[cbd] the line weights that identify cables (≥ 0.9 pt) and enclosure outlines (≤ 0.3 pt) on cable block diagrams.

[project.rack_panels] which panel a PLC rack sits in when it is not <rack>-PLC (e.g. MCC1 = "MCC-PLC"). A run warns when the default names a panel no drawing shows, and says which line to add. Racks a package does not have are ignored, so several packages' entries can sit together.

[review] enabled false (default): the register is for printing and marking up by hand. true: decision columns, carry-forward, waivers and No Longer Raised (section 12).

[project] description_prefix the project text that starts every channel description (07.11 SHIPLOADER). Normally left unset: it is detected from the package and ignored when channel headings are compared.

rules.toml · waivers.toml

rules.toml: per rule, enabled and severity.

waivers.toml: [[waiver]] entries with id, rule, subject, reason, approved_by, expires. Applied only with review on.

All three files feed the run's config hash, recorded in every review.json, so a result can always be tied to the settings that produced it.

15How accuracy is measured

Findings are only worth having if they are right. Every rule is tested two ways.

  • Synthetic sheets. Tests build small PDFs inside the test itself, laid out like the client's (same grid frame, title block, SHX annotations and line weights), with one deliberate fault. Each rule has a pass case and a fail case. These never depend on client drawings.
  • The answer key. Issues the checker has confirmed as real in the sample package are numbered AK-001 to AK-023, each with a test that requires the platform to report it. Confirmed correct drafting that must not be reported is numbered AK-N02 to AK-N07. A code change that loses one of them fails the tests.

16Limits

  • Built for this client's drafting standard. CBD cables are 0.96 pt runs and enclosures are 0.24 pt dash-dot outlines; another drafting house's weights are set in [cbd] in the config. Template readers recognise this package's layouts; a new layout gets identifiers only and a NO_TEMPLATE issue.
  • Termination drawings. The readers are built against the sample package's current, old-standard termination sheets and must be re-checked when the new-standard sheets arrive. Their candidates (C-29 to C-34) are on hold until then. Wire numbers at the field device's own terminals are read but not checked, because which device a terminal belongs to is unreliable where device boxes are stacked.
  • Positions are inferred from text. Tag positions are label positions; labels sit one or two rows above their symbol, and the checks allow for that.
  • Short wire numbers on schematics are accepted only near the cell they name, or along a straight run from it; boxed terminal markings such as A1/T1 on a relay are not read as wires. WIRE-005 reports a wire label drawn away from the cell it encodes.
  • Scanned sheets are flagged, not read. Sheets plotted without SHX notes (PDFSHX = 0) are flagged NO_SHX_TEXT and should be re-plotted. With --ocr they are decoded from their letter strokes instead: letters are fingerprinted (each path's points relative to the letter, to 0.25 pt), learned from the SHX notes on the readable sheets, and matched exactly. A word with any unmatched letter is dropped, absence rules (TAG-003, WIRE-002, COMP-001, DRW-003, TAG-007, PLC-006, COMP-002, TERM-001/003/004, and TAG-005 when the home sheet is decoded, as a relay's contact table there may not have decoded; PATH-001, COMP-005, DEV-003 and WIRE-004 when a CBD or termination sheet is decoded) stay quiet about decoded sheets, a decoded sheet keeps its file-name identity, and its findings are marked. [ocr] confirm_decoded = true holds back findings that rest only on decoded sheets.
  • Parked work, kept in the plan but not being built: M6 OCR and AI assist (PLC-002 description matching), M7 Word report and revision-to-revision comparison, M8 the electrical equipment list (DEV-001, DEV-002 and a full equipment list output).

TAG-004Grid Validation
On its home sheet, the tag label is not near the grid cell its tag encodes. Labels are drawn above their symbol, so up to 2 rows above and 1 column either side is accepted. Uses the label position until symbol positions are read (M3).		MINORgrid
TAG-005Duplicate Device Tag
A device tag drawn as a device on its home sheet and again, as a device, on another schematic sheet: its label sits where its own grid reference says, as a copied device would, rather than elsewhere as a reference. Typically a copied sheet that was not renumbered (S-TN27D2 on sheets 027 and 028).		MAJORgrid
TAG-006Identifier Spelling Variant
An identifier written differently from its canonical form (e.g. SPL-JB-1 for SPL-JB1).		MINORclaims
TAG-007Auxiliary Contact Pointer
A relay coil's contact table entry ('43/D4' under K-TN19F1 on sheet 019) must point to an auxiliary contact labelled with the coil tag (K-TN19F1) near grid D4 of sheet 043. A contact labelled with the coil sheet plus its own grid (K-TN19D4) is wrong (checker, C-05).		MAJORgrid
Wire Validation
WIRE-001Wire Number Format
Text that starts like a wire number of this package (a known FFI and a digit) but does not fit <FFI><Sheet><Grid>, e.g. TN36D (grid digit missing) or TN3D6 (one-digit sheet).		MAJORclaims
WIRE-002Wire Home Sheet
A wire number is used, its home sheet (the sheet it encodes) is in the package, but that sheet does not show it. Same check as TAG-003, for wires.		MAJORgrid
WIRE-003Duplicate Wire Number
One wire number used for two different signals: in the channel rows of two PLC channels on the schematics, or on terminals of two different PLC modules on the slot termination sheets. Commons and supplies shared by one module's terminals, and wires looped from device to device in a JB, are not reported.		MAJORlinked model
WIRE-004Wire Continuity
A wire number the schematic channel row shows for a device that its JB terminals on the termination drawing do not have.		MAJORlinked model, terminations, traces
WIRE-005Wire Grid
On its home sheet, a wire number is not drawn near the grid cell it encodes. A wire is numbered where it starts and labelled there, so 'C2' drawn at C6 is numbered from the wrong end (401104-176). A wire carried to another sheet ('16D2') is checked at its origin. Same tolerance as TAG-004.		MINORgrid

PLC-001Channel Match
The schematics and the termination drawings put a device, or a wire, on different PLC slots: the device's JB terminals go to another slot than its schematic channel, or a slot termination sheet lands a wire on a module whose schematic channels do not have it.		MAJORlinked model, terminations, traces

PLC-004Safety Module Consistency

PLC-005Module Capacity

PLC-006Module Type Match

PLC-007Slot / Sheet Consistency
The slot number on a slot sheet (title, RACK line, POINTS) must agree, and the rack layout's sheet reference for each slot must be that sheet, once.		MAJORclaims
PLC-008POINTS Notation

PLC-009Panel / Slot Consistency
A JB terminal's destination on the termination drawing ('LTL-PLC ... DI SLOT 12') names a slot that panel does not have, or a module of a different I/O type.		MAJORlinked model, terminations

18Glossary

Answer key (AK)
Issues the checker confirmed as real (AK-nnn) or as correct drafting (AK-Nnn), each held by a test.
Candidate (C-nn)
A finding raised for the checker's ruling, before it is confirmed, rejected or withdrawn.
CBD
Cable block diagram: enclosures, devices and the cables between them.
Claim
One fact from one place on one sheet, read by one reader. Never edited; everything else points back to claims.
Corroborated
A node or edge seen by two or more document types.
Designation
IEC location name, =K07.11+LTL-JB1: function after =, location after +.
Edge
A typed link between two nodes (CHANNEL_DEVICE, ROUTE, TERMINAL_DEVICE…), keeping the claims behind it.
FFI
First field identifier: the two letters (TN) that tie a tag or wire number to a drawing.
Fingerprint
A finding's identity across runs and revisions, built from names and grid cells, not run IDs or coordinates.
Hop
One step of a signal trace: device, wire, JB terminal, JB, panel, slot, channel.
JB · LCS
Junction box; local control station. Both are field locations a signal passes through.
Left out
An input type excluded from a run with --exclude: listed, not checked.
Node
One thing in the engineering model (a device, wire, JB, panel, module, channel or terminal), however many sheets show it.
Not sourced
A hop only a left-out or unsupplied document type could show. Never counted as a gap.
Orphan
A device on a CBD that no PLC channel reaches.
Register
QA_Register.xlsx, where the checker records decisions.
SHX annotation
The invisible AutoCAD note holding each piece of plotted text; the source of all text the platform reads.
Signal trace
The path of one PLC signal from field device to channel, across all drawings.
Superseded
An old designation with a configured replacement (LTL-AUT1 → LTL-PLC): linked through, still reported.
Waiver
A known, accepted exception in waivers.toml, matched by rule and subject pattern.
